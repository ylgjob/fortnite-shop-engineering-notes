Prove a Fortnite Shop Import Can Recover After a Midway Failure

November 24, 2026

A shop import often writes a rotation record and then writes hundreds of offers. Losing a connection halfway through can leave a day in the archive with only part of its shop. Retrying without cleanup can add duplicate offers or give readers two different histories for the same date.

Make the published snapshot one unit

Write into staging or use a database transaction. Attach a confirmed snapshot to the public date only after the records and counts pass validation. When routing readers to a snapshot, use the public pointer rather than automatically selecting the latest staging row. Imports for the same rotation should preserve one logical identity.

Interrupt the test at a meaningful boundary

Arrange a fixture with two sections. Force the second write to fail after the first succeeds. The public archive should retain the last complete record or show a clear unavailable state. Retry with the same rotation and verify both sections appear once. Repeat with two concurrent retries and check the final record count.
